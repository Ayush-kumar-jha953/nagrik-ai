# NAGRIK AI — Data-Driven Civic Solutions

> **Prioritizing our problems. Turning civic complaints into actionable information.**

NAGRIK AI is a civic issue reporting and assistance platform focused on helping people document local problems, share them with a community, and understand which public authority may be responsible. The project combines a Flask web application, a text moderation component, and a separate AI complaint assistant.

> **Project status:** The main Flask application is the integrated user-facing platform. `UPKAR-ML/` is also included as a standalone message-checker app, and `UPKAR-LLM/` is a separate Streamlit complaint assistant. These separate apps are not all launched by one command. Read [Architecture and integration status](#architecture-and-integration-status) before running them.

## Overview

Local civic problems—such as damaged roads, garbage accumulation, broken streetlights, waterlogging, and public-service issues—can be difficult to report, track, and communicate clearly. NAGRIK AI provides a shared interface for recording these problems and displaying them in a community feed.

The project includes three main pieces:

1. **Main civic platform (`app.py`)** — a Flask application with a browser-based interface, posts, categories, comments/likes, issue statistics, a SQLite database, and AI-generated guidance for civic complaints.
2. **UPKAR-ML (`UPKAR-ML/`)** — a standalone Flask web app and API that classifies Hindi/English messages as `good`, `bad`, or `unclear`.
3. **UPKAR-LLM (`UPKAR-LLM/`)** — a standalone Streamlit assistant that helps turn a citizen's description into a structured complaint, suggests relevant authorities and escalation paths, and can inspect uploaded photos through its configured AI tools.

The project is currently oriented toward **Delhi-specific civic guidance** in the main application. Suggestions generated by an AI model should be checked against current official sources and the relevant local authority.

## Features

### Main civic platform

- Create and browse community posts about civic issues.
- Select a civic category, add a description and location, and optionally upload an image.
- Support for categories including Climate, Healthcare, Education, Sanitation, and Infrastructure.
- Like posts and participate through comments.
- View issue counts grouped by category.
- Store user, post, comment, and interaction data in SQLite.
- Apply text moderation to the title and description before saving a new post.
- Generate AI-based civic guidance and suggested authorities for Delhi-related reports when the configured Groq model is available.
- Assign a basic zone and map coordinates based on configured location-name rules.

### UPKAR-ML message checker

- Standalone Flask page and `/predict` endpoint.
- Hindi (Devanagari) and English text preprocessing.
- Uses a trained `LinearSVC` model and `CountVectorizer` features.
- Returns `good`, `bad`, or `unclear`, with a rough decision-strength indicator.
- Includes a `/health` endpoint.

### UPKAR-LLM complaint assistant

- Streamlit chat interface for English, Hindi, and Hinglish descriptions.
- Helps structure a complaint and suggest an authority and escalation route.
- Supports optional photo uploads and image-related tools.
- Can save structured complaints to a local JSON Lines file and produce summaries.
- Uses Groq when configured; availability and results depend on the API key, selected model, network access, and provider limits.

## Requirements

- Python 3.10 or newer is recommended.
- `pip` and a terminal/command prompt.
- Internet access for installing packages and for AI API calls.
- A Groq API key is optional for the main app's rule-based fallback, but required for the hosted-model features and for the standalone LLM assistant.

The main app uses SQLite, so **PostgreSQL is not required** for the bundled main application. The frontend uses ordinary HTML, CSS, and JavaScript; Node.js/npm is not required.

## Run the main application

Run these commands from the repository root (`NAGRIKAI/`).

### 1. Create and activate a virtual environment

**Windows PowerShell**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

**macOS / Linux**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Configure environment variables

Copy `.env.example` to `.env` and update the values:

**Windows PowerShell**

```powershell
Copy-Item .env.example .env
```

**macOS / Linux**

```bash
cp .env.example .env
```

Open `.env` and set a strong secret key. Add a Groq API key if you want AI-generated guidance from the hosted model. See [Environment variables](#environment-variables).

### 4. Start the app

```bash
python run.py
```

Then open the local URL printed in the terminal. In the default Flask development configuration this is usually:

- <http://127.0.0.1:5000>

If port 5000 is already in use, stop the other process or configure a different port in your local run command/code.

## Environment variables

The root `.env.example` documents these settings:

| Variable | Required? | Purpose |
|---|---|---|
| `SECRET_KEY` | Strongly recommended | Flask session signing key. Replace the development fallback before deployment. |
| `GROQ_API_KEY` | Optional for main-app fallback; needed for hosted-model calls | API key used by the Groq client. |
| `GROQ_MODEL` | Optional | Preferred model name for the Groq API. |
| `DATA_DIR` | Optional | Directory for persistent database/upload data when the app is configured to use it. |

Never commit `.env`, real API keys, passwords, or personal data. If a key was ever exposed publicly, revoke it and create a replacement.

## Using the application

1. Open the main application in your browser.
2. Use the profile/login interface to create or access a demo account.
3. Open the post/report action and enter the civic issue category, title or description, location, and optional image.
4. Submit the report. The app checks the text and may reject content that matches its moderation rules.
5. Browse posts in the feed and use available community actions such as likes and comments.
6. Review the issue category counts and any AI guidance shown with a report.
7. Log out using the UI if available, or use the logout route/action exposed by the app.

Use demo content while testing. Do not upload private, identifying, or sensitive information to screenshots or sample records.

## Standalone ML message checker

This is a separate Flask app under `UPKAR-ML/`. Its model and vectorizer are loaded from a folder named `model/` in the app's code. The archive currently contains a directory named `Model/` with a capital **M**. On case-sensitive systems, rename it to lowercase `model/` or update the path in `UPKAR-ML/app.py` to match the actual directory.

### Run it

```bash
cd UPKAR-ML
python -m venv .venv
```

Activate the environment using the instructions above, then run:

```bash
pip install -r requirements.txt
python app.py
```

Open <http://127.0.0.1:5000>. If the main Flask app is already using port 5000, run the ML app on another port, for example:

```bash
flask --app app run --port 5001
```

### API

`POST /predict`

Request JSON:

```json
{
  "message": "Please repair the pothole near the school."
}
```

Example response shape:

```json
{
  "label": "good",
  "confidence": 0.73,
  "score": -0.99
}
```

The numbers above illustrate the response format only; actual values depend on the message and trained model. `confidence` is a rough signal-strength estimate, **not a calibrated probability**.

`GET /health` returns a basic health response.

### Retraining

Open `UPKAR-ML/notebooks/training.ipynb` in Jupyter or Google Colab. Confirm that the notebook's dataset path points to `UPKAR-ML/dataset/indian_civic_language_moderation_hindi_english.csv`. Keep preprocessing in `preprocess.py` consistent with the notebook, and place the resulting `model.pkl` and `vectorizer.pkl` in the model directory expected by the app.

**Model-quality warning:** The supplied dataset contains synthetic/template-generated messages. A high test score on similarly templated data is not proof of real-world moderation quality. Evaluate with realistic, independently collected examples and inspect false positives and false negatives before relying on the model.

## Standalone LLM complaint assistant

The Streamlit assistant lives in `UPKAR-LLM/` and is a separate program from the main Flask app.

### Run it

```bash
cd UPKAR-LLM
python -m venv .venv
```

Activate the environment, then install the dependencies:

```bash
pip install -r requirements.txt
```

Create a `.env` file in `UPKAR-LLM/` and provide a Groq key:

```dotenv
GROQ_API_KEY=your_groq_api_key_here
```

Then start Streamlit:

```bash
streamlit run app.py
```

Open the local address printed by Streamlit, commonly <http://localhost:8501>.

### Typical workflow

1. Describe the issue in the chat in English, Hindi, or Hinglish.
2. Optionally upload photos through the sidebar.
3. Review the structured complaint and suggested authority / escalation route.
4. Use the saved-complaints panel to review or download records if that feature is available in the running app.
5. Ask for an area-level summary when you have complaint records to summarize.

The assistant's complaint data is stored in `UPKAR-LLM/data/complaints.jsonl`, not automatically in the main application's SQLite database.

## API overview

The main Flask app exposes JSON routes used by the frontend. The exact request fields and response shapes are defined in `app.py`; common routes include:

| Route | Method | Purpose |
|---|---|---|
| `/` | GET | Render the main page |
| `/api/session` | GET | Return the current session/user view |
| `/api/login` | POST | Log in or create an account |
| `/api/logout` | POST | Clear the current session |
| `/api/categories` | GET | Return issue counts by category |
| `/api/posts` | GET | Retrieve posts with optional category/search/zone/pagination filters |
| `/api/posts` | POST | Create a civic post |
| `/static/uploads/<filename>` | GET | Serve uploaded images |

The app contains additional routes for post interactions and complaint-related features. Consult `app.py` for the complete route list and current request/response schemas.

## Database and uploaded files

- The main app uses SQLite, with the database path defined in `database.py`.
- The bundled `nagrik.db` may contain example records. Back it up before experimenting if you want to preserve the supplied data.
- Uploaded images are stored locally by default. A `DATA_DIR` can be used for persistent storage when configured as supported by the deployment setup.
- The standalone LLM assistant saves its own complaints as JSON Lines in `UPKAR-LLM/data/complaints.jsonl`.
- The main app and standalone assistant do not automatically share one complaint store.

For a fresh local demo, back up the database first. Only remove or reset the database if you intentionally want to discard its contents.

## Architecture and integration status

The main Flask app imports `ml_filter.py` and `civic_llm.py`, so text checks and AI civic guidance are called from the main application's post-creation flow. The `UPKAR-ML/` folder also contains a separate model-serving Flask app, and `UPKAR-LLM/` contains a separate Streamlit app.

These are not one unified process:

- The main app's `ml_filter.py` performs rule-based moderation checks; it does not automatically call the standalone `UPKAR-ML` HTTP API.
- The main app's `civic_llm.py` provides the main app's AI guidance. The standalone `UPKAR-LLM` assistant is launched separately and its JSONL records are not automatically inserted into the main SQLite database.
- The optional local image classifier/object detector mentioned in the standalone assistant are not included as working model modules in this archive. Do not describe those capabilities as an active local detection pipeline unless you add and configure the required models.

## Known limitations

- The main app is a prototype and should not be considered production-ready without a security and reliability review.
- AI-generated authority guidance can be incomplete or outdated; confirm the responsible authority and official contact details.
- The location-to-zone mapping is based on a small set of name keywords and fixed coordinates. It is not a verified geospatial service or a reliable urgency-ranking model.
- The main app's rule-based text filter is not a comprehensive multilingual moderation system and can miss abuse or flag benign text.
- The standalone ML model is trained on a synthetic/template-generated dataset. High accuracy on this dataset may not generalize to real citizens' messages.
- The standalone ML checker and main app use separate moderation implementations.
- The LLM assistant is a separate app; its saved records are not automatically synchronized with the main feed.
- Local SQLite files and uploaded images may be lost on ephemeral hosting unless persistent storage is configured.
- Debug/development settings should not be used in a public production deployment.

## Security notes

Before public deployment:

- Set a long, random `SECRET_KEY`.
- Keep API keys and credentials in environment variables or the hosting provider's secret manager.
- Disable Flask debug mode and use a production WSGI server.
- Validate file content and file size, not only file extensions.
- Add authentication/authorization checks to every private or state-changing API route.
- Add rate limiting, CSRF protection where applicable, logging, backups, and error monitoring.
- Review privacy, retention, and consent requirements for uploaded photos and location data.
- Do not treat AI-generated recommendations as official government decisions.

## Deployment

Deployment configuration files are included at the repository root (`Procfile`, `render.yaml`, and `DEPLOY.md`). Review `DEPLOY.md` before deploying.
